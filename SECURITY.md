# Security

## Reporting a vulnerability

Open a private security advisory on GitHub (Security → Report a vulnerability) or email the maintainer via the address on the GitHub profile. Please don't file public issues for security problems. You'll get a response within a few days.

## What Folio can and cannot do

- **Read-only.** SnapTrade OAuth apps cannot place, modify or cancel trades, and cannot move money. Folio requests only the `read`, `openid` and `email` scopes.
- **No data path through third parties.** Portfolio data (accounts, balances, positions, activities) travels directly between Raycast on your Mac and `api.snaptrade.com`, authenticated with your own Bearer token.
- **No analytics, no telemetry.** Folio makes no network calls other than SnapTrade's API, SnapTrade's OAuth endpoints, and the auth worker described below.

## Where secrets and tokens live

| Item | Location | Notes |
| --- | --- | --- |
| OAuth `client_secret` | Cloudflare Worker secret | Never in the extension, never in git. Rotatable in the SnapTrade dashboard + `wrangler secret put`. |
| Access / refresh tokens | Raycast's OAuth token store on your Mac | Written with `OAuth.PKCEClient.setTokens`. Sign-out revokes at SnapTrade (one retry), then deletes them locally either way; the UI says if the revoke failed. |
| Privacy-mode flag | Raycast LocalStorage | A boolean. |
| Cached API responses | Raycast Cache on your Mac | 60–120 s TTL for fast reopening. Cleared on sign-out and on Refresh. |
| Dev-only Personal API key | Raycast password preference | Off by default. Only for developers running against their own SnapTrade account. |

## The auth worker

SnapTrade dashboard OAuth apps are confidential clients: token exchange, refresh and revocation require HTTP Basic `client_id:client_secret` in addition to PKCE. That secret can't ship inside an extension, so [`auth-worker/`](auth-worker/) performs exactly those three calls. Design constraints:

- **Stateless.** No KV, no database, no logging of request bodies. Tokens pass through in transit only.
- **Anyone can call it, so it must not be able to do anything harmful on its own.** It can only turn an authorization code plus its matching PKCE verifier into tokens (both already in the caller's hands), rotate a refresh token the caller already holds, or revoke a token the caller already holds. It cannot read accounts, mint tokens without a code, or redirect anywhere: `redirect_uri` is checked against an exact-match allowlist before anything reaches SnapTrade.
- **Only discovery-published upstream URLs.** The token and revocation endpoints come from SnapTrade's `/.well-known/oauth-authorization-server`, validated to be `https` on the issuer's host.
- **Input limits.** JSON bodies are capped at 16 KB, PKCE verifiers are validated against RFC 7636, and every response is `Cache-Control: no-store` with no CORS headers, so web pages cannot call it from a browser.
- **Rate limited** per client IP (30 requests/minute) via a Workers rate-limit binding.
- **If the secret leaks**, rotate it in the SnapTrade dashboard and re-run `wrangler secret put`. Existing user sessions keep working because refresh uses the new secret transparently.

## Token handling in the extension

- PKCE with S256 and a fresh `state` per attempt, generated by Raycast's OAuth client. The callback's `state` is verified by Raycast before the code is handed to Folio.
- Refresh tokens rotate. The extension replaces both tokens atomically and single-flights refreshes within a process. If a refresh fails with `invalid_grant`, the session is cleared and the user is asked to sign in again rather than retrying with a dead token.
- On a 401 from the API the extension refreshes once and retries once, then signs out.
- The `id_token` is decoded (not verified) solely to display your email on the sign-in screen. It is never sent to any API.

## Known limitations

- Cached API responses live in Raycast's cache directory on disk in plaintext for their TTL. Anyone with access to your user account on the Mac could read recent balances from there until sign-out or the next refresh overwrites them. Use privacy mode and sign out if that matters in your environment.
- Rate limiting is per Cloudflare location and best-effort, as documented by Cloudflare. It deters abuse; it is not an accounting system.
